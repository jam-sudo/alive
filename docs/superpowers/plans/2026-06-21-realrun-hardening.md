# CARTOGRAPHER Real-Run Hardening Implementation Plan

> **Status update (2026-07-19): IMPLEMENTED / historical.** 이 hardening은 완료된 `TG-K562-v1`
> run에 반영됐다. 본 plan은 provenance를 위해 보존하며 재실행 지시가 아니다.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the remaining `TG-K562-v1` scientific-run blockers — write-once run immutability (#4 / audit P1-2) and protein-sequence provenance separation (#5 / audit P2-1) — plus the P3-1 duplicate-write nit, so that the real K562 A100 run is permitted by spec §11.3.

**Architecture:** The run identifier becomes an immutable composite hash of *config + data card + raw-expression data + protein-sequence mapping* (owner-confirmed option (a), 2026-06-21), so the same config pointed at different data yields a different `run_id` and a different run directory — structurally preventing the §11.2 config↔data mismatch. `prepare` refuses to reuse an existing run directory, every stage refuses to overwrite a non-byte-identical artifact, the ledger becomes strictly append-only (no entry replacement), and upstream stages lock after a terminal state or sealed access. Protein-sequence provenance is recorded as its own data-card fields and ledger artifact, independent of the raw-expression URI.

**Tech Stack:** Python 3.11–3.12, numpy/scipy/scikit-learn/anndata, `uv` env + lockfile, `pytest`, `ruff` (line length 100). Hashing via `hashlib.sha256` and the existing `alive.provenance` helpers (`sha256_file`, `sha256_json`).

## Global Constraints

- Python **3.11–3.12** only (scientific-stack wheels); `uv sync` / `uv run` for all commands.
- Ruff line length **100**; `uv run ruff check src tests` and `uv run ruff format --check src tests` must pass.
- **No hardcoded** paths, split IDs, thresholds, feature lists, seeds, or hyperparameters in `src/` (CLAUDE.md#repo).
- **TDD**: every step writes a failing test first, then the minimal code (superpowers:test-driven-development).
- Per CLAUDE.md#verify, run targeted unit tests + **provenance tamper/resume tests** for every artifact/immutability change; run **leakage tests** for any data/eval change.
- **run_id (owner-confirmed option (a), 2026-06-21):** `run_id = sha256_json({"config": config_digest, "data_card": data_card_digest, "raw_data": raw_data_sha256, "sequence_mapping": sequence_mapping_sha256})[:16]`. The config-only digest keeps its current `sha256(serialised_config)[:16]` algorithm but is **renamed** `Config.config_digest`.
- **Ledger is append-only**: `RunLedger.record_artifact` is the only write path; replacing an existing entry is forbidden (it already raises `DuplicateArtifactError`).
- **Write-once stages**: a stage whose output already exists must refuse to re-run unless the regenerated bytes are identical (spec §11.2).
- **Out of scope (deferred):** the A100 real-model ESM smoke test (spec §4.3 / §11.3) is hardware-gated and cannot run on the M5; it remains an open precondition recorded in the spec, not a task here. No scientific run is started by this plan.

```python
def compute_run_id(
    config_digest: str,
    data_card_digest: str,
    raw_data_sha256: str,
    sequence_mapping_sha256: str,
    *,
    length: int = 16,
) -> str:
    """Immutable composite run identifier (spec §11.2).

    Binds the config to the exact data, raw expression file, and protein-sequence
    mapping it was prepared against, so the same config on different data yields a
    different ``run_id``.
    """
    serialised = json.dumps(
        {
            "config": config_digest,
            "data_card": data_card_digest,
            "raw_data": raw_data_sha256,
            "sequence_mapping": sequence_mapping_sha256,
        },
        sort_keys=True,
        separators=(",", ":"),
    )
    return hashlib.sha256(serialised.encode("utf-8")).hexdigest()[:length]
```

def _append_artifact(run_dir: Path, name: str, checksum: str) -> None:
    """Append an artifact to the ledger; write-once (raises on any re-record)."""
    ledger = RunLedger.read(run_dir / "ledger.json")
    ledger.record_artifact(name, checksum)  # DuplicateArtifactError on second record
    ledger.write(run_dir / "ledger.json")


def _refuse_nonidentical_rerun(run_dir: Path, name: str, checksum: str) -> bool:
    """Return True if this stage is a byte-identical no-op; raise if it differs."""
    ledger = RunLedger.read(run_dir / "ledger.json")
    try:
        existing = ledger.artifact_sha(name)
    except LedgerError:
        return False  # not recorded yet → first run
    if existing == checksum:
        return True  # byte-identical re-run → no-op
    raise CliError(
        f"stage output {name!r} already exists with a different hash; runs are "
        "immutable (spec §11.2). Start a new run instead of re-running this stage."
    )
```

Then each stage computes its artifact, calls `_refuse_nonidentical_rerun` (return early if `True`), writes outputs, and calls `_append_artifact`. Apply to `cmd_fit` (`base_artifact`), `cmd_develop` (`method_lock`), `cmd_calibrate` (`conformal_artifact`).

def _assert_upstream_unlocked(run_dir: Path) -> None:
    """Refuse upstream re-runs after a terminal state or sealed access (spec §11.2)."""
    futility_path = run_dir / "futility.json"
    if futility_path.exists():
        status = json.loads(futility_path.read_text(encoding="utf-8")).get("status")
        if status == "FUTILITY_STOPPED":
            raise CliError(
                "run is FUTILITY_STOPPED (terminal); upstream stages are locked. "
                "Start a new run for any further confirmatory attempt."
            )
    audit_path = run_dir / "audit.jsonl"
    if audit_path.exists() and audit_path.read_text(encoding="utf-8").strip():
        raise CliError(
            "the sealed cohort has been accessed; upstream stages are permanently "
            "locked for this run (spec §11.2)."
        )
```
